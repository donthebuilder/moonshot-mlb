# Game simulator v2 — all three recommendations, shipped

Date: 2026-09-03 · `lib/gameSim.js`, `components/GameSimPanel.js`,
`components/tabs/Games.js` · verified against tonight's 15 games, 4,500
simulated games per calibration run

---

## 1. The running game — and the calibration gap is closed

The v1 engine had no steals, no errors and no wild pitches, and came in ~0.5
runs a game light. All three are now in, every input off the slate row:

    attempt      season_sb_attempt_rate
    success      season_sb / (season_sb + season_cs), blended against the
                 catcher's opp_catcher_cs_rate and the pitcher's own
                 sb_against / sb_attempts_against
    wild pitch   pitcher_wp9
    error        opp_def_success_rate

**Calibration, 4,500 simulated games across tonight's slate:**

| per game | sim | MLB |
|---|---|---|
| runs | 8.88 | 8.6 |
| hits | 16.82 | 16.6 |
| home runs | 2.35 | 2.3 |
| strikeouts | 17.43 | 16.4 |
| walks | 6.97 | 6.2 |
| **stolen bases** | **1.52** | 1.45 |
| **caught stealing** | **0.41** | 0.36 |
| **errors** | **1.18** | 1.2 |
| home win% | 49.7 | 53 |

Runs, hits, homers, steals and errors all land. Three notes where they don't:

**K and BB run ~5% and ~12% high.** That is one night's fifteen games, not the
league — tuning the engine to match a single slate's arms would be overfitting,
so I left it and wrote the number down instead. Worth re-checking across a week.

**Home win% is still ~3pp light.** `HFA` is now 1.03 and it is exported, named,
and commented as the one constant in the file not derived from a published
field. I did not crank it until the number hit 53: one slate cannot tell an
absent home-field effect from a night where the away teams had the better
pitchers, and a fudge factor sized to hit a target is not a measurement.

**One fitted number, declared.** `season_sb_attempt_rate` is published without
its denominator documented, and at face value it produced 0.67 steals a game.
Rather than invent a denominator, `RUN.ATTEMPT_SCALE = 1.27` scales it until the
sim reproduces the league's steal count — named at the top of the file where you
can see it, with a note to delete it if the bot ever publishes attempts and
opportunities separately.

**Unearned runs are handled properly.** A run that scored off an error, and the
automatic runner in extras, are both excluded from ERA. Charging either would
have quietly inflated every pitcher line in the box.

## 2. The box score panel

`components/GameSimPanel.js`, mounted in the Games tab under each game after the
lineups (`#gp-sim-<game_pk>`). Collapsed by default and it **simulates nothing
until opened** — 2,000 games is ~250ms of main thread, which is fine on demand
and rude on every card of a fifteen-game slate. Memoised on the game, so
re-rendering doesn't re-run it.

**The card leads with the distribution, not the box score.** Win probability and
the run spread first; the box score below it, captioned "one game out of 2,000 —
not a prediction," with a *play another* button. A single draw shown first reads
as a forecast, and this thing should never read as a forecast.

Box lines are clickable and open the same player modal as the rest of the site.
Homer rows are the only ones with emphasis. The footer states what the sim
couldn't know: numbered relief arms (the board publishes no individual
relievers), a short lineup card, or an unconfirmed home side.

## 3. The convergence read

Inside the panel: the top six hitters by **simulated homer odds**, next to their
**`hr_score`**, and the gap between their ranks.

    Justin Foscue     21.9%    39    agree
    Jake Burger       20.8%    44    agree
    Ezequiel Duran    18.3%    22    sim likes +4

These are genuinely independent — nine innings of simulated plate appearances
versus a weighted signal blend — so agreement is worth more than either alone.
A gap of two places or less is uncoloured, because everything colour-coded is a
claim and rank noise isn't one. **It does not average them into a third number:**
a blend of two models is not a third opinion.
